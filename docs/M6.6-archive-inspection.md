# M6.6 — Archive inspection gate

**Purpose:** a downloaded package must pass byte-integrity verification, format-aware archive inspection and recipe hash matching before the Store may expose READY_TO_INSTALL.

## Implemented

- nexus_txn/inspectors.py inspects ZIP files using Python's standard library, without extracting or writing any member.
- Each regular file is streamed through SHA-256 and its actual expanded byte count is checked against ZIP metadata.
- ZIP paths are rejected when absolute, traversing, ambiguous, backslash-based, control-character/reserved, case-colliding or aimed at protected system locations.
- Symbolic links, special filesystem entries and encrypted ZIP entries are rejected.
- Configurable limits cover compressed archive size (64 MiB default), member count (4,096), one expanded member (128 MiB), total expanded size (512 MiB) and compression ratio (200:1).
- The inspector catches malformed ZIP/CRC errors and reports a deterministic failure rather than extracting partial content.
- match_recipe() verifies every declared recipe source exists in the inspected ZIP and that its SHA-256 matches the recipe. Extra archive entries are reported as unmapped; they are never implicitly installed.
- nexus_txn/store_pipeline.py joins recipe validation, archive inspection and recipe hash matching to the Store state machine.
- Store stages now include INSPECT between VERIFY and READY_TO_INSTALL. A failed or unsupported inspection moves the flow to FAILED.

## PSU and SAS: recognized, not parsed

PSU and SAS are separate declared formats. The dispatcher returns status: unsupported for both and does not attempt to open them as ZIP. The Store pipeline consequently fails closed. A genuine PSU/SAS parser and format-specific tests are still required before either can reach an install-ready state.

## Safety boundary

This milestone is inspection-only. It does not extract archives, invoke post-install actions, mount storage, write a PS2 device or install a package. READY_TO_INSTALL means the host-side package checks passed; it does not mean installation happened or that the package is authentic.

The SHA-256 comparison establishes consistency with the supplied recipe/catalog digest. It is not publisher authentication. Signed catalog trust, original M5 Bridge compatibility and a native PS2 installer remain separate milestones.

## Validation

New regression coverage includes path traversal, absolute paths, protected paths, case collisions, size/count limits, ZIP content hashes, recipe mismatch, unsupported PSU/SAS handling and Store state transitions. The GitHub Actions result is the authoritative test count for the committed tree.
