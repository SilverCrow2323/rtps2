# M6.23 — read-only availability checks for Files roots

M6.23 adds an explicit availability check for the three fixed storage roots already listed by Files:

- mass:/ — USB mass-storage namespace
- mmce0:/ — MMCE slot 0
- mmce1:/ — MMCE slot 1

## User flow

1. Activate FileXio from System using the existing Triangle → warning → Cross flow.
2. Open Files and press **Square** to check all three roots.
3. The three right-side status cards show ACCESSIBLE, NOT ACCESSIBLE, or PROBE ERROR.
4. Use Up/Down to select a root. Triangle still opens the existing scan confirmation; Cross confirms the separate read-only library scan and Circle cancels it.

A root check is not a scan. It calls only fileXioDopen() followed by fileXioDclose(); it does not enumerate entries with Dread, recurse, inspect files, or add titles to the catalog.

## Interpretation and safety boundary

- ACCESSIBLE means FileXio successfully opened and closed that exact allowlisted root at the time of the probe.
- NOT ACCESSIBLE means the root could not be reached through the currently registered IOP filesystem services. This does not prove that a physical device is absent; its driver or filesystem may simply not be loaded/registered.
- PROBE ERROR means an unexpected open error or a close failure occurred.
- Before FileXio is explicitly activated, the result remains NOT PROBED.
- Inputs outside the three fixed roots are rejected.
- The probe never loads USB/MMCEMAN drivers, mounts or unmounts volumes, resets the IOP, or writes to storage.
- Triangle's separate scan remains behind its existing confirmation and only inspects the configured direct CD/, DVD/, and POPS/ children.

## Regression coverage

The host-native tests cover:
- no FileXio calls before explicit activation;
- all three fixed roots and the status mapping;
- rejection of arbitrary paths;
- a failed Dclose becoming a probe error;
- no directory enumeration during a probe;
- Square being ignored while FileXio is inactive or while a scan confirmation is pending;
- the existing scan confirmation and catalog insertion behavior remaining intact.
