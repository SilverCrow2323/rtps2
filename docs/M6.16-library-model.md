# M6.16 — Native game-library index

M6.16 introduces a bounded in-memory catalog model that future read-only storage providers can populate. It is intentionally independent of HDD/MMCE/USB filesystem drivers and does not invent scan results.

## Data model

The EE module keeps a fixed array of up to 96 entries. Each entry contains:

- A 64-bit stable key (unique within its source).
- Source: internal HDD, MMCE or USB.
- Platform: PS2 or PS1.
- Backend hint: AUTO, OPL, Neutrino or POPS.
- Title, optional title ID, source path and byte size.
- Favorite state.

The key must be generated by the provider from stable source/title identity. A provider must detect collisions before inserting entries. Same key values may exist on different sources.

## Index behavior

- Upsert replaces metadata for an existing (source, key) pair and retains an existing favorite state.
- New entries are kept in deterministic order: ASCII case-insensitive title, title ID, source, then key.
- The view state supports source, platform and favorites-only filters.
- Four view modes are represented: Grid, Carousel, Coverflow and List.
- Selection movement wraps around the currently visible entries.
- Empty indexes and invalid inputs are handled without allocating dynamic memory.

The Games page now distinguishes an empty catalog from a catalog containing entries. It also reports that the native index is ready while storage providers remain unconnected.

## Boundaries

This is a model and view-state layer, not a filesystem scanner. It does not open paths, mount devices, parse OPL/Neutrino/POPS formats, launch games, persist favorites, or decode cover art. The four-slot M6.15 cache remains empty until a future provider and image decoder explicitly populate it.

No filesystem writes or boot-critical changes are made.

## Verification

The native regression test covers deterministic sorting, same-key/different-source identity, source/platform filters, favorites retention across metadata refresh, circular selection, view-mode validation, malformed fixed-width strings and empty-state behavior. The PS2DEV cross-build also links the module into NEXUS.ELF. The latest host CI run is linked from the repository's verified status page.
