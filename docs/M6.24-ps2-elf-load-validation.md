# M6.24 — PS2 EE ELF load-segment validation

## Why this gate exists

A valid-looking ELF header is not enough to prove that the payload contains anything a PS2 loader can map. The previous host verifier checked the ELF32/little-endian/MIPS/ET_EXEC header and the declared program-header table bounds, but it did not inspect the program-header entries. A file with only PT_NULL entries, or a PT_LOAD range extending beyond the file, could therefore pass the architecture gate.

## New validation contract

The native artifact gate now requires:

- ELF32, little-endian, current ELF version, ET_EXEC and EM_MIPS;
- a non-empty program-header table whose entries fit inside the file;
- at least one PT_LOAD entry;
- every PT_LOAD entry to satisfy p_filesz <= p_memsz;
- every file-backed PT_LOAD range to remain inside the ELF payload;
- the existing entry-point and optional section-table bounds checks.

The host regression fixtures cover absent tables, non-loadable headers, out-of-file load segments and file-size/memory-size inconsistencies. The PS2DEV workflow continues to build NEXUS.ELF, run this verifier and record the artifact digest before upload.

## What this does not prove

This is a structural host-side gate. It does not certify the R5900 ABI/CPU flags, prove that the program's runtime dependencies are available, boot the binary in PCSX2, or validate a physical PS2. The existing PCSX2 and physical-console validation boundaries remain unchanged.
