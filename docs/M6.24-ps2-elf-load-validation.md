# M6.24 — PS2 EE ELF load-segment validation

## Why this gate exists

A valid-looking ELF header is not enough to prove that the payload contains anything a PS2 loader can map. The previous host verifier checked the ELF32/little-endian/MIPS/ET_EXEC header and the declared program-header table bounds, but it did not inspect the program-header entries. A file with only PT_NULL entries, an entry point outside executable memory, or a PT_LOAD range extending beyond the file could therefore pass the architecture gate.

## New validation contract

The native artifact gate now requires:

- ELF32, little-endian, current ELF version, ET_EXEC and EM_MIPS;
- `e_flags` must identify the MIPS III architecture family used by the PS2 EE toolchain (the other ABI/extension bits are retained and reported, not hard-coded);
- a non-empty program-header table whose entries fit inside the file;
- at least one PT_LOAD entry;
- every PT_LOAD entry to satisfy p_filesz <= p_memsz;
- every file-backed PT_LOAD range to remain inside the ELF payload;
- every PT_LOAD memory range to remain inside the 32-bit address space;
- non-trivial PT_LOAD alignment to be a power of two, with congruent file and virtual offsets;
- the ELF entry point to lie inside a PT_LOAD segment marked executable;
- the existing optional section-table bounds and section-name index checks.

The host regression fixtures cover absent tables, non-loadable headers, out-of-file load segments, file-size/memory-size inconsistencies, invalid alignment, non-MIPS-III architecture flags and entry points outside executable memory. The PS2DEV workflow continues to build NEXUS.ELF, run this verifier and record the artifact digest before upload.

## What this does not prove

This is a structural host-side gate. It checks the ELF architecture field for MIPS III, but does not certify every R5900 ABI/CPU-specific extension or prove that runtime dependencies are available. It does not boot the binary in PCSX2 or validate a physical PS2. The existing PCSX2 and physical-console validation boundaries remain unchanged.
