# M6.3 — Store Manager planning layer

## Implemented

- Catalog schema checks for IDs, names, tags and non-negative installed sizes.
- Curated profiles (`base`, `gaming`, `network`, `developer`) using catalog tags. Profiles are filters, not compatibility claims.
- Dependency-ordered install preview.
- Install/update/keep actions and conservative update peak-space estimate (old plus new installed size).
- Three-valued storage result: `pass`, `insufficient`, or `unknown`. Unknown capacity never silently passes.
- Removal preview blocks removal of packages still required by installed packages.
- Dedicated terminal progress/plan renderers, intended for a separate full-screen screen.

## Deliberate boundaries

This is a host-side planner. It does not contact Store, Bridge, PS2 or a filesystem target. It does not download, unpack ZIP/PSU/SAS, verify remote signatures, write packages, remove files or execute a package recipe. Catalog metadata must be authenticated and validated before a future client trusts it.

## Next integration work

1. Bind catalog transport to authenticated Companion/Bridge protocol and define trust policy.
2. Add archive format handlers as separate adapters (ZIP, PSU, SAS); never infer format from `title.cfg`.
3. Add target-specific free-space providers with checked units and filesystem semantics.
4. Port the plan model to PS2 UI and run the workflow in a dedicated full-screen terminal/TUI with cancellable phases.
5. Implement a separately reviewed native writer only after target path recipes, rollback limits and boot-critical exclusions are specified.
