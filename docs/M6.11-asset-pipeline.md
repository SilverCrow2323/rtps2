# M6.11 — NEXUS asset pipeline

M6.11 establishes a deterministic path from the six original section PNGs to a GS-ready texture payload. This is the host-side asset stage; it does not claim that the PS2 renderer already uploads or displays the atlas.

## Source set

Place these 64×64, 8-bit RGB/RGBA PNGs in one directory: games.png, ps1.png, homebrew.png, store.png, files.png and system.png.

The atlas is 256×128 pixels, arranged as four columns by two rows. Six cells are occupied; two remain reserved for later dashboard/system glyphs.

## Build

    python tools/nexus_asset_pack.py pack \
      --icons assets/icons \
      --output build/nexus-icons.nxa \
      --preview-png build/nexus-icons-preview.png \
      --manifest build/nexus-icons.json

    python tools/nexus_asset_pack.py verify build/nexus-icons.nxa

The converter uses only Python's standard library. It supports non-interlaced 8-bit RGB/RGBA PNGs, validates chunk CRCs, bounds dimensions and compressed payload sizes, and rejects unknown critical chunks, unsupported filters and malformed/trailing data.

## NXA1 container

| Field | Value |
|---|---|
| Header | 64 bytes, little-endian |
| Magic / version | NXA1 / 1 |
| Pixel format | GS PSMCT32 RGBA byte order |
| Atlas | 256×128 |
| Payload | 131,072 bytes, row-major |
| Integrity | SHA-256 over the complete pixel payload |
| Alpha | PNG 0–255 scaled to GS 0–128 (0 transparent, 128 opaque) |

The payload follows the header immediately. Texture dimensions are powers of two. No palette, mipmap or swizzle transform is applied; upload code must pass the GS format and stride to libdraw.

## Memory budget

The icon atlas payload occupies 128 KiB of GS local memory before allocator block alignment. The later cover-art cache is a separate budget and must use bounded LRU slots; it must not pin every cover in VRAM. The M6.10 double 640×512 RGBA32 framebuffer allocation accounts for 2.5 MiB before page alignment and other GS allocations.

## Boundary

M6.11 supplies source art, deterministic packing, metadata and host verification. It does not yet alter the native ELF or issue GS DMA uploads. The next renderer step must validate texture transfer, CLUT-free PSMCT32 sampling, alpha blending, VRAM slot accounting and visual output on a real console before marking the atlas as displayed.
