# M6.17 — Read-only game catalog scanner core

M6.17 adds a bounded directory scanner that turns an explicitly configured, already-mounted filesystem root into entries in the M6.16 native catalog.

## Scanner contract

`NexusScanFsOps` supplies only three callbacks: open directory, read one directory entry, close directory. There is no write, remove, rename, mkdir, format, mount or unmount callback in the interface.

The scanner first opens and closes the configured root to confirm that it exists. It then reads only these fixed child directories:

| Directory | Platform | Accepted files |
|---|---|---|
| `CD/` | PS2 | `.iso`, `.zso` |
| `DVD/` | PS2 | `.iso`, `.zso` |
| `POPS/` | PS1 | `.vcd` |

The folder layout follows the file-based OPL structure; MMCE paths follow MMCEMAN's documented `mmce0:/` and `mmce1:/` device namespaces. The root is passed in by a future mount/provider layer; NEXUS does not mount a device here.

References:
- PS2SDK fileXio directory and read-only mount flags: https://ps2dev.github.io/ps2sdk/file_xio_8h.html
- MMCEMAN device namespace and driver requirements: https://github.com/ps2-mmce/mmceman
- OPL CD/DVD folder and ISO/ZSO conventions: https://www.ps2homebrew.org/Open-PS2-Loader-User-Guide/tree-structure.html

## Safety rules

- Root paths are checked for traversal, malformed device syntax, control characters and unsafe components.
- Directory entries must be safe basenames. Names containing separators, colon, control characters or missing NUL termination are rejected.
- The scanner is deliberately non-recursive. It will not walk arbitrary nested trees.
- Only the explicitly selected source/platform subfolders are opened.
- Each scan is staged in a bounded 96-entry buffer. A directory read failure prevents the staged batch from being committed.
- Only supported file extensions are inserted. Unsupported CSO/CHD and USBExtreme `ul.*` sets are not guessed or partially parsed.
- Image sizes are 64-bit in the library model; this avoids truncating files above 4 GiB.
- Repeated scans upsert the same source/path identity and keep an existing favorite. Entries no longer found are not removed yet; source reconciliation/cleanup will be a separate atomic catalog operation.

## Important storage distinction

This is a file/directory scanner, not an APA partition parser. USB, MMCE and an already-mounted file-based HDD root can use the adapter contract. Traditional APA internal-HDD games stored as HDLoader partitions need a separate, read-only APA/PFS provider and are **not** discovered by this scanner.

MMCEMAN documents that IOMANX and fileXio must already be loaded before it is initialized. This milestone does not load IRX modules, initialize MMCEMAN, mount storage or touch a device. The native fileXio adapter and module lifecycle are still pending.

## Current integration boundary

The scanner core and fake in-memory filesystem tests are committed. The renderer reports supported formats and clearly shows that the mounted-volume adapter is not connected yet. No real storage scan has run and the Games list should remain empty until an actual provider is initialized.

## Verification

Host regression tests cover root validation, OPL/POPS extension filters, 64-bit file sizes, unsafe entry names, missing optional folders, staged failure behavior and idempotent catalog upsert. Native PS2DEV cross-build and complete CI are tracked in the repository status page.
