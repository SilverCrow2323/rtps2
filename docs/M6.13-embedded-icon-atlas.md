# M6.13 — Embedded NEXUS icon atlas

M6.13 closes the boot-time gap between the host PNG pipeline and the native GS atlas renderer. The six source PNGs are tracked in the repository, NXA1 is regenerated during the native build, and the pack is linked into the ELF as aligned read-only data.

## Boot flow

1. GitHub Actions checks out the six source files in assets/icons/.
2. The standard-library host tool tools/nexus_asset_pack.py validates every PNG chunk and emits assets/build/NEXUS-ICONS.NXA.
3. src/nexus_asset_blob.S includes that generated pack in .rodata, aligned to 16 bytes. The nexus_icon_pack_start and nexus_icon_pack_end symbols delimit the exact NXA1 byte range.
4. nexus_renderer_init() calls nexus_atlas_upload() only after the GS framebuffer and GIF DMA setup are ready.
5. The EE validator checks NXA1 structure and computes SHA-256 over the complete 131,072-byte pixel payload before allocating VRAM.
6. On success, the renderer uses the six 64×64 atlas cells. If validation, allocation or upload fails, the dashboard retains its procedural 5×5 glyphs and renderer initialization continues.

No runtime USB/HDD asset lookup is needed for these six built-in section icons.

## Memory and safety boundaries

- Embedded pack: 131,136 bytes (64-byte header + 131,072-byte payload), stored in ELF read-only memory.
- GS atlas allocation: 131,072 bytes before allocator block alignment.
- Only one icon atlas slot is allocated. There is no cover-art LRU, multi-slot texture cache or runtime hot reload.
- SHA-256 detects accidental corruption; it does not authenticate a publisher. NXA1 is not a signature format.
- The build output assets/build/ and src/NEXUS.ELF are generated artifacts and are not source-controlled.

## Reproducible build

    python3 tools/nexus_asset_pack.py pack --icons assets/icons --output assets/build/NEXUS-ICONS.NXA --manifest assets/build/nexus-icons.json
    python3 tools/nexus_asset_pack.py verify assets/build/NEXUS-ICONS.NXA
    make -C src clean
    make -C src

The native workflow executes the pack step before invoking the PS2DEV EE toolchain, so the assembler .incbin target always exists for the cross-build.
