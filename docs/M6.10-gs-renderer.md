# M6.10 — Native GS graphical renderer

**Purpose:** replace the debug-text-only dashboard with a real PS2 GS framebuffer renderer while preserving the native shell's input and page model.

## PS2SDK libraries

The renderer uses official PS2SDK components:
- libgraph for video region, VRAM allocation, GS initialization, framebuffer output and VSync.
- libdraw for GS drawing environment, filled rectangles, frame selection and frame completion.
- libfont for the ROM KROM FontX renderer.
- libpacket and libdma for GIF packet allocation and DMA channel submission.

No external graphics framework or generated font file is required.

## Display and framebuffers

- Fixed logical width: 640 pixels.
- Height follows the console region: 512 lines PAL or 448 lines NTSC.
- Two 32-bit GS framebuffers are allocated in VRAM.
- The renderer draws into the back buffer, submits a GIF DMA packet, waits for completion/VSync and switches the displayed framebuffer.
- A bounded 60,000-qword render packet is allocated once and reused.

## NEXUS visual system

The bootstrap renderer introduces the first actual SPDW/NEXUS palette:
- deep navy background,
- layered blue panels,
- cyan accent and selection state,
- high-contrast white text,
- muted blue-grey secondary text,
- amber warning / not-probed state.

The dashboard presents six status chips (Disc, MC0, MC1, HDD, MMCE, USB), followed by a 3×2 section-card layout for Games, PS1 Library, Homebrew, NEXUS Store, Files and System. Section screens use the same topbar, content panel, next-step indicator and navigation footer.

Device values remain NOT PROBED until real providers are implemented. Section copy explicitly distinguishes host-only Store capabilities from native PS2 functionality that is still pending.

## Fallback

The debug text renderer remains as a fallback if GS setup, KROM font loading or packet initialization fails. This prevents a failed graphics initialization from leaving the user with a blank screen and keeps an operator-visible route to the current state.

## Remaining boundary

The build proves that the code compiles and links against PS2SDK; it does not prove that the UI has been visually validated on a real TV/monitor or that every video mode behaves correctly on console hardware. A physical boot and visual test are still required.

The current renderer is a first graphical shell, not the final animated design system. It does not yet include original icon atlases, cover artwork, GS texture upload/cache, animated backgrounds, per-page widgets, storage discovery, game scanning or OPL/Neutrino handoff. Those remain separate, testable increments.

No filesystem is mounted or written and no boot manager is modified.
