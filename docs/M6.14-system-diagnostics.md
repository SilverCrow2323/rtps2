# M6.14 — System diagnostics and PCSX2 smoke-test path

M6.14 makes the System page useful as a first graphics/input smoke-test screen and adds a small PCSX2 launcher for MX Linux.

## System page

The page reports:
- PAL 640×512 or NTSC 640×448 geometry selected by the renderer
- NXA1 ICON ATLAS READY when the built-in atlas passed validation and GS upload
- PROCEDURAL ICON FALLBACK when the upload path is unavailable
- Controller state for port 0

Storage probes deliberately remain pending. A controller being connected does not imply that HDD, memory-card, MMCE or USB storage has been detected.

## PCSX2 launcher

tools/run_nexus_pcsx2.sh accepts an optional ELF path. It prefers the installed PCSX2 Flatpak, grants it read access only to the ELF's parent directory, and falls back to pcsx2-qt when available. It checks that the file exists before launch and preserves spaces in paths.

Run from the repository:

    bash tools/run_nexus_pcsx2.sh
    bash tools/run_nexus_pcsx2.sh "/path/with spaces/NEXUS.ELF"

See [PCSX2-MX-LINUX.md](PCSX2-MX-LINUX.md) for the setup, official Flatpak and GitHub artifact download steps.

## Automated launcher regression

tests/test_pcsx2_launcher.sh uses fake Flatpak/Qt executables to test:
1. Flatpak invocation and scoped filesystem permission with a path containing spaces.
2. Native Qt fallback when the Flatpak app is unavailable.
3. Clear exit status for a missing ELF.

These tests validate argument handling only; they do not boot PCSX2, emulate GS hardware, or prove the image looks correct.
