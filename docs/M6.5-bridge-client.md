# M6.5 — Companion/Bridge client core

## Implemented

`nexus_txn.bridge.BridgeClient` is a host-side client core with an injected transport. It sends bearer authentication without printing credentials, validates catalog records and package identifiers, rejects unsafe API paths, requests byte ranges, checks HTTP 206 and Content-Range boundaries, persists a resumable `.part` cache, and verifies the final byte count and SHA-256 before atomically promoting the cache file.

The transport is injected deliberately. The exact M5 Companion/Bridge source snapshot and its route definitions are not currently available in this checkout, so this module does not invent endpoints or claim wire compatibility. Catalog and package paths are configurable; the defaults are provisional interface placeholders and must be matched to the recovered Bridge implementation.

## Download contract

A transport callable receives `(method, path, headers, body)` and returns an object with `status`, `headers` and `body`. Range responses must use HTTP 206 and a valid `Content-Range` whose start, end, total and body length match the request and catalog metadata. The local PC cache is resumable across interrupted runs. A partial file is retained on verification failure for inspection; it is never promoted as a verified package.

## Security boundary

- Bearer token is never emitted in logs or result objects.
- Package IDs and API paths are constrained.
- Package bytes are cached on the host only.
- SHA-256 and advertised size are checked before promotion.
- No archive extraction, PS2 storage write, installer invocation, signature trust or TLS implementation is performed by this module.
- SHA-256 verifies integrity against catalog metadata; it does not authenticate the catalog publisher. A signed catalog/trust policy remains required.

## Validation

The fake transport tests cover catalog validation, auth header, chunked range download, resume from a partial cache, HTTP failure, malformed Content-Range, hash mismatch and unsafe identifiers/paths.
