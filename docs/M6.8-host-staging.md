# M6.8 — Recipe-scoped host staging

**Purpose:** transform a verified ZIP into a minimal host-side payload that the transaction reference engine can consume, without installing to a real target.

## Implemented

- nexus_txn/staging.py validates the recipe, re-inspects the ZIP and rechecks every mapped source path and SHA-256 before creating a staging directory.
- The staging directory is created under an explicit caller-supplied cache root. A symbolic-link cache root is rejected.
- Only recipe-mapped files are copied. Unmapped documentation, screenshots and other archive entries are not copied.
- Files are streamed manually from ZipFile.open into newly created files. The code does not call extract() or extractall(), does not preserve archive permissions and hashes the bytes again while writing.
- The staging manifest maps validated source paths to validated recipe destination paths and carries the expected SHA-256 for the transaction engine.
- remove_staged_package() only removes a direct child with the NEXUS staging prefix under the supplied staging root.
- Store flow now requires VERIFY → INSPECT → STAGE → READY_TO_INSTALL. Failed staging blocks install readiness.
- The manifest is exercised end-to-end against the existing host transaction engine using a disposable sandbox target and state directory.

## Mutation and race resistance

Staging repeats archive inspection and recipe matching rather than trusting an earlier report. A test modifies the ZIP after the INSPECT stage; the STAGE operation detects the changed bytes and fails closed. During extraction each mapped file is streamed, counted and hashed again. A partial staging directory is removed on failure.

## Safety boundary

This milestone creates files only in the explicit host cache/staging directory chosen by the caller. The integration test commits only to a temporary test sandbox. The transaction engine remains a host reference and must not be pointed at a real PS2 mount. No MC, MMCE, USB, PFS or HDD target is mounted or written. No PS2 installer is invoked.

Only ZIP can be staged. PSU and SAS remain unsupported and fail closed. READY_TO_INSTALL means the package is staged for a future installer adapter; it does not mean the package is installed.
