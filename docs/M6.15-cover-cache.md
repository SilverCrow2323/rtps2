# M6.15 — Four-slot GS cover-art cache

M6.15 adds a bounded native texture-cache layer for cover artwork. The cache is deliberately small and predictable: four fixed 128×128 PSMCT32 slots, allocated together as a 512×128 GS surface.

## Implemented

- Four 128×128 RGBA32 slots with a total raw payload budget of 256 KiB (65,536 GS 32-bit words).
- One contiguous GS VRAM allocation; each slot's base is computed from the fixed slot stride.
- Upload path uses aligned EE memory, PS2SDK texture-transfer commands, GIF DMA drain/completion and an explicit texture flush.
- Cache policy maintains slot validity, keys and recency; hits reuse their existing slot and misses select a free or least-recently-used slot.
- A failed allocation or upload does not advertise stale pixels as a valid cache entry.
- Renderer initialization reserves the cache after the embedded 128 KiB NXA1 icon atlas. The System page reports whether the cover-cache reservation succeeded.
- The policy is separated into a small native module so its LRU decisions can be tested on the host.

## Memory budget

| Resource | Raw GS allocation |
|---|---:|
| Double 640×512 RGBA32 framebuffers | 2.5 MiB |
| Embedded NXA1 icon atlas | 128 KiB |
| Four-slot 128×128 cover cache | 256 KiB |
| Total before allocator/page alignment | 2.875 MiB |
| Nominal remainder in 4 MiB GS local memory | 1.125 MiB |

These are arithmetic budgets, not a promise of the exact free memory returned by the allocator. Alignment, other GS allocations and display configuration still matter. The cache is fixed at four slots; it is not a general dynamic VRAM allocator.

## Integration boundary

The native cache can reserve slots, accept RGBA32 cover pixels and draw a cached slot. The game-library artwork provider is not yet connected: no scanner currently resolves a game's cover path, decodes source artwork or schedules uploads as the selection changes. The cache does not imply that every game already has a displayed cover.

The next step is to connect the game-library metadata/source layer to this cache, with bounded decode buffers and deterministic fallback artwork. Avoid increasing the number or size of slots until framebuffers and real GS output have been measured on hardware.
