# M6.18 — Explicit PS2SDK fileXio adapter

M6.18 connects the M6.17 read-only scanner core to the PS2SDK FileXio directory API. The adapter is available to NEXUS, but **it is deliberately not activated during normal boot**.

## Activation boundary

Call `nexus_filexio_activate()` only from an explicit user action after the NEXUS bootstrap has initialized SIF RPC. It:

1. Checks whether the PS2SDK IOMANX module (`IOX/File_Manager`) is already loaded.
2. Checks whether the FileXio RPC module (`IOX/File_Manager_Rpc`) is already loaded.
3. If one or both are missing, enables the PS2SDK SBV patches required by the embedded IRX sample and loads only the missing embedded IRX images.
4. Calls `fileXioInit()` and marks the adapter ready.

It does **not** call `SifIopReset()`, reset the IOP, start USB mass/MMCEMAN/APA drivers, mount or unmount any volume, format a device or write files. Existing module installations are reused. If the activation attempt fails, NEXUS keeps running and the adapter remains unavailable for retry/inspection.

The IOMANX and FileXio IRX images are embedded in the ELF using the same PS2SDK `bin2c` build pattern as the upstream FileXio sample. The IOMANX binary is the PS2SDK legacy-hook build intended to coexist with the older IOMAN interface. No automatic module initialization is wired into `main()`.

## Read-only directory adapter

The adapter implements only:

- `fileXioDopen()`
- `fileXioDread()`
- `fileXioDclose()`

It does not expose `fileXioOpen`, `fileXioWrite`, `fileXioMount`, `fileXioUmount`, delete, rename or format operations to the scanner.

The DREAD result is converted to the scanner's fixed-width entry type. Regular files and directories are identified from `iox_stat_t.mode`; symlinks and special entries are treated as unsupported and never traversed. File sizes preserve the high and low 32-bit fields.

The scanner still opens only explicitly configured direct roots and the fixed `CD/`, `DVD/`, `POPS/` children. Examples of roots a future UI/provider may offer are `mass:/`, `mmce0:/` and `mmce1:/`, but a root is usable only if its device driver and filesystem are already registered and accessible. This adapter does not make a device appear.

## Internal HDD distinction

A file-based root can expose ISO/ZSO folders. Traditional APA/PFS internal-HDD game partitions are not regular folders under this scanner and require a distinct read-only APA/PFS provider. This milestone does not enumerate those partitions.
