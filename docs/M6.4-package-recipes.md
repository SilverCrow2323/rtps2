# M6.4 — Package recipe validation

## Implemented
`nexus_txn.recipes.validate_recipe()` validates package installation intent without executing it. It requires an explicit package ID/version, archive format (`zip`, `psu`, `sas`), target class (`mc0`, `mc1`, `mass`, `mmce`, `pfs`), non-empty file mapping, SHA-256 per file, optional dependency IDs and a constrained post-install action.

It rejects traversal, absolute paths, backslash paths, protected boot/system paths, duplicate destinations (case-insensitive), malformed hashes, duplicate dependencies, unknown targets, unknown formats and unapproved post-install actions. The returned record explicitly carries `execution_enabled: false`.

## Important distinction
Recognizing `psu` or `sas` in recipe metadata does not mean a parser or extractor exists. PSU remains a savedata archive format, not ZIP. SAS packages require a format-specific implementation. This milestone does not inspect archive bytes, verify a package signature, download, extract, write a device or execute a post-install action.

The transaction and recipe path validators now explicitly reject Windows-style backslash paths as well as traversal and protected destinations. Regression coverage was added for both code paths.

## Next
Bind validated recipes to the real M5 Companion/Bridge catalog, recover the M5 package inspector, then add format-specific inspectors and a signed catalog trust policy. Only after that should the native PS2 UI expose a confirmation step.
