# M6.12 — Native GS atlas upload path

M6.12 adds a native EE-side NXA1 upload and sampling module using PS2SDK libgraph/libdraw.

## Implemented

- Strict NXA1 v1 header and exact payload-size checks for the fixed 256×128 PSMCT32 atlas.
- 16-byte DMA source-alignment check before transfer.
- A single 128 KiB GS VRAM texture allocation using block alignment.
- GIF DMA upload through `draw_texture_transfer`, followed by `draw_texture_flush` and a DMA wait before the packet is released.
- PSMCT32 RGBA texture setup with nearest filtering and no CLUT.
- Six 64×64 atlas cells sampled from the four-column/two-row layout, with half-texel inset to reduce edge bleed.
- Dashboard cards use the atlas when an upstream caller has loaded it; the existing 5×5 procedural glyphs remain the fallback.
- Atlas texture state is rebound immediately before drawing each icon because KROM text rendering can change GS texture state.

## Integration boundary

The native API is exposed as `nexus_atlas_upload(pack, size)`. The current shell does **not** yet load `NEXUS-ICONS.NXA` from a mounted device or embed the pack in the ELF, so the atlas is not automatically active at boot. The future read-only asset provider must read the file into a 16-byte-aligned buffer and call this API.

The native upload routine validates the container structure and exact dimensions/length, but does not calculate SHA-256 on EE. The caller must verify the NXA1 payload digest before passing the buffer. Host-side `nexus_asset_pack.py verify` already performs this cryptographic integrity check. Do not treat header validation as publisher authentication.

The allocator currently reserves one atlas slot. `graph_vram_free` is FIFO-style in PS2SDK, so release/replacement must remain coordinated with later VRAM allocations; this is not yet a general-purpose LRU cache.

## Verification still required

- PS2DEV cross-build and CI syntax checks.
- Real-console DMA upload, texture sampling, alpha appearance and PAL/NTSC visual inspection.
- Runtime asset loading and native SHA-256 verification.
- Measured VRAM accounting before introducing cover-art cache slots.

A successful cross-build proves the native code compiles and links, not that the atlas has been displayed on hardware.
