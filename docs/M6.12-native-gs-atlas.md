# M6.12 — Native GS atlas upload and integrity

M6.12 adds a native EE-side NXA1 upload and sampling path using PS2SDK libgraph/libdraw, plus local SHA-256 verification before the DMA upload can touch GS VRAM.

## Implemented

- Strict NXA1 v1 header, dimensions, reserved bytes and exact payload-size checks for the fixed 256×128 PSMCT32 atlas.
- Allocation-free SHA-256 implementation in `src/nexus_sha256.c`; the digest stored at NXA1 header bytes 20–51 is checked against the complete 131,072-byte payload.
- A mismatched payload or header digest is rejected by `nexus_atlas_validate_pack` before VRAM allocation.
- 16-byte DMA source-alignment check before transfer.
- A single 128 KiB GS VRAM texture allocation using PS2SDK block alignment.
- GIF DMA upload through `draw_texture_transfer`, followed by `draw_texture_flush`; the channel is drained before submission and completion is awaited before the packet or source buffer can be released.
- Packet allocation/data and DMA-send errors are handled without marking the atlas ready; failed allocations are released.
- PSMCT32 RGBA texture setup with nearest filtering and no CLUT.
- Six 64×64 atlas cells sampled from the four-column/two-row layout, with half-texel inset to reduce edge bleed.
- Dashboard cards use the atlas when an upstream caller has loaded it; the existing 5×5 procedural glyphs remain the fallback.
- Atlas texture state is rebound immediately before drawing each icon because KROM text rendering can change GS texture state.

## Integrity test coverage

The native SHA-256 test checks the standard empty-string and `abc` vectors, padding boundaries at 55/56/63/64/65 bytes, the full 128 KiB NXA payload size, and a one-million-byte input. The NXA regression test rejects both modified image bytes and a modified header digest.

## Integration boundary

The native API is exposed as `nexus_atlas_upload(pack, size)`. M6.13 closes the startup integration gap: the host packer generates NEXUS-ICONS.NXA and src/nexus_asset_blob.S embeds it into the ELF; nexus_renderer_init() passes the aligned byte range to this API after GS and DMA initialization. See [M6.13 embedded icon atlas](M6.13-embedded-icon-atlas.md).

The digest is an integrity check, not publisher authentication. NXA1 has no signature; trust in a future downloaded asset must come from the signed catalog and its pinned key chain, not from SHA-256 alone.

The allocator currently reserves one atlas slot. `graph_vram_free` is FIFO-style in PS2SDK, so release/replacement must remain coordinated with later VRAM allocations; this is not yet a general-purpose LRU cache.

- PS2DEV native EE cross-build: [workflow #33](https://github.com/SilverCrow2323/rtps2/actions/runs/44577115974) passed after linking `nexus_sha256.o`; the boot-time embedded atlas is verified in [M6.13 build #42](https://github.com/SilverCrow2323/rtps2/actions/runs/44579819621).
- Host CI: [workflow #178](https://github.com/SilverCrow2323/rtps2/actions/runs/44577288782) passed the Python suite, compile checks, navigation regression, NXA1 integrity regression, SHA-256 known vectors and native shell syntax checks.
- Real-console DMA upload, texture sampling, alpha appearance and PAL/NTSC visual inspection are still required.

A successful cross-build proves the native code compiles and links, not that the atlas has been displayed on hardware.
